# CUBIC ORDEAL

**CUBIC ORDEAL** は、巨大な立方体が奥から転がり込む浮遊足場で、進路の予測・位置取り・捕獲の順番を同時に管理する、独自制作のブラウザ向け3Dリアルタイム空間パズルです。Reactは画面枠と操作UIだけを担当し、3D描画はBabylon.js、ゲーム判定は固定時間のTypeScriptシミュレーションが担当します。

> この作品は既存作品の名称、ロゴ、映像、音楽、3Dモデル、フォント、問題配置、攻略データを使用していません。ゲームの抽象的な「進路予測と床印による捕獲」という発想を、独自の問題・名称・美術・ルール表現として再構成しています。

現行実装の正本、PR #1の削除監査、文書間の優先順位は[CURRENT_STATE.md](./CURRENT_STATE.md)にまとめています。

## はじめ方

開発環境では、プロジェクト直下で次のコマンドを実行します。`pnpm dev` の後に表示されるローカルURLを開くとタイトル画面が表示されます。

```bash
pnpm dev
```

| コマンド                   | 用途                                                           |
| -------------------------- | -------------------------------------------------------------- |
| `pnpm dev`                 | Vite開発サーバーを起動する。                                   |
| `pnpm puzzles:write`       | TypeScript正本から88問JSONと検証レポートを再生成する。         |
| `pnpm puzzles:check`       | 生成物と正本の完全一致、および全88問の解法を検査する。         |
| `pnpm check`               | TypeScriptの型検査を行う。                                     |
| `pnpm test`                | 固定グリッド、捕獲、足場、得点、88問の検証を実行する。         |
| `pnpm test:e2e`            | ChromiumとWebKitで各モード、保存復帰、モバイル操作を検査する。 |
| `pnpm test:e2e:production` | Expressで実ビルドを起動し、本番経路を検査する。                |
| `pnpm build`               | 本番用の静的ビルドを生成する。                                 |

## 操作方法

### パソコンとゲームパッド

| 行動                | キーボード            | ゲームパッド               |
| ------------------- | --------------------- | -------------------------- |
| 移動                | 矢印キー / WASD       | 左スティック               |
| MARKの設置・CAPTURE | Space / Z             | A / Cross相当              |
| MARKの解除          | Backspace / Delete    | Y / Triangle相当           |
| AREAの作動          | X / E                 | X / Square相当             |
| FAST                | C / Shiftを押し続ける | B / Circle相当を押し続ける |
| 一時停止            | Escape                | Start相当                  |

### スマートフォン

縦画面では上側に3D盤面、下側に操作面を配置します。左下の仮想スティックで走り、右下の**MARK / CAPTURE / CLEAR**、**AREA**、押している間だけ有効な**FAST**で操作します。MARKを置いたあと、キューブがまだ印へ来ていない状態で再入力しても印は消えません。解除は画面のCLEAR、Backspace／Delete、ゲームパッドのY相当で行います。操作面は`pointerdown`、`pointerup`、`pointercancel`を処理するため、指がボタンの外へ出ても移動やFASTが残らないようになっています。安全領域は`safe-area-inset`を考慮します。カメラは固定し、画面上の方向と盤面の方向を一致させます。

## ルール

| 要素       | 意味                                       | 正しい扱い                                                                                                      |
| ---------- | ------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| **NORMAL** | 明るい石灰色の必須回収キューブ。           | MARKの上でCAPTUREする。取り逃すと損失に数える。                                                                 |
| **VEIL**   | エメラルドの回路線を持つ必須回収キューブ。 | CAPTUREすると同じ位置へ緑のAREAアンカーを残す。                                                                 |
| **VOID**   | マゼンタの亀裂を持つ黒曜石キューブ。       | 捕獲せず、足場の端から落とす。捕獲すると足場を1列失う。                                                         |
| **MARK**   | プレイヤーの選択タイルへ置く青い捕獲印。   | 同時に1つだけ置ける。キューブが印の真上にある時だけCAPTUREし、対象不在時の印は保持する。解除は専用CLEARで行う。 |
| **AREA**   | VEILから作られた緑の範囲捕獲アンカー。     | 全アンカーが同時に3×3範囲を処理する。対象がないときはアンカーを消費しない。MARK上のVOIDは保護される。           |

NORMALまたはVEILの取り逃しはLOSSメーターへ加算されます。メーター上限は盤面幅マイナス1で、超過時はプレイヤー側の足場が1列崩壊します。全必須キューブを回収し、VOIDを捕獲せず、取り逃しがない問題は**PERFECT**となり、足場が1列追加されます。

## 得点と MIND INDEX

通常のMARK捕獲は100点、AREA捕獲は200点です。PERFECTは規定回転数より少なければ10,000点、同じなら5,000点、多ければ1,000点を加算します。ステージを完了した時点では残り足場1列につき1,000点を加算します。

評価名は**MIND INDEX**です。これは既存作品の評価式を利用しない独自計算で、次式を0〜999へ丸め込みます。

```text
round(score / 170 + stage × 18 + remainingRows × 9 − misses × 22)
```

## モード

| モード       | 内容                                                                                                                                |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| **TUTORIAL** | 本編アーカイブ外の手設計8ゲートで、移動、MARK、CAPTURE、VEIL、VOID保護、AREA、LOSS、PERFECTを順に学ぶ。                             |
| **CAMPAIGN** | Stage 1からFinalまでの全88問を進める本編。公開ランキング用の表示名が必要で、問題完了時にローカル進行を保存する。                    |
| **PRACTICE** | Stage、Wave、Puzzleを選択して練習する。名前入力やランキング通信なしで、10秒巻き戻し、クイックセーブ／ロード、一手送りを利用できる。 |
| **CREATE**   | 幅4〜7、奥行2〜9の独自盤面を塗り、名前入力やランキング通信なしで検査、localStorage保存、JSON書き出し、テスト実行を行う。            |
| **DUEL**     | 同じ問題を交代で解き、先に5点、4対4以降は2点差を付けた方が勝つローカル対戦。名前入力やランキング通信は不要。                        |

TUTORIALは各操作を一つずつ実演する独立した小問です。現在のゲートで不要なMARK／CLEAR／AREA入力は受け付けず、ゲート達成後に次の小問へ進みます。最後のPERFECTだけは取り逃しなしの再試行が必要です。

公開表示名はCAMPAIGNを開始するときだけ必須です。TUTORIAL、PRACTICE、CREATE、DUELは名前なしで直ちに開始でき、ランキング用のSupabase RPCも呼び出しません。CAMPAIGNの開始RPCが通信系の一時障害で失敗した場合はローカルプレイを続け、結果画面から同じ開始IDを再送します。

## ステージと問題数

本編は9ステージ・88問です。`client/src/game/stagePlan.ts`と`client/src/game/puzzles.ts`を唯一の編集元とし、`client/public/data/puzzles.json`を決定的に生成します。ゲームは開始時にこのJSONを読み込み、CIはJSONと正本の完全一致を検査します。各問題にはID、ステージ、ウェーブ、サイズ、規定回転数、難易度タグ、初期配置、攻略手順、生成seed、検査情報が含まれます。詳細は[LEVEL_VALIDATION_REPORT.md](./LEVEL_VALIDATION_REPORT.md)を参照してください。

| 範囲    | Wave構成           | 問題数 |
| ------- | ------------------ | -----: |
| Stage 1 | 4×2, 4×2, 4×3, 4×4 |     12 |
| Stage 2 | 4×5, 4×5, 4×6, 4×6 |     12 |
| Stage 3 | 5×4, 5×5, 5×6, 5×6 |     12 |
| Stage 4 | 5×7, 5×7, 5×8, 5×8 |      8 |
| Stage 5 | 6×6, 6×6, 6×7, 6×7 |     12 |
| Stage 6 | 6×8, 6×8, 6×9, 6×9 |      8 |
| Stage 7 | 7×7, 7×7, 7×8, 7×8 |     12 |
| Stage 8 | 7×8, 7×9, 7×9, 7×9 |      8 |
| Final   | 7×9を4ウェーブ     |      4 |

Stage 1のWave 1（3問）はAREAを使わず、VOIDを避けながら列を読む手設計です。Wave 2（3問）はVEILからAREAを作り、3×3範囲の外側を手動捕獲する手設計です。Wave 3–4（6問）は、分岐・交差・角・編み込み・往復・周回の手設計ルートで、AREAを覚えた後も次の安全マスを読む局面を続けます。Stage 2のWave 1–2（6問）は、千鳥・分岐・単線・編み込み・ゲート・往復の手設計ルートでAREAを使わずにルートを読みます。Wave 3–4（6問）はAREAを3回連鎖させながら外側の列を手動捕獲する手設計です。Stage 3のWave 1–2（6問）は幅5列へ広げ、中央分断・外側分岐・長い編み込み・帰還を手設計で学ばせます。Wave 3–4（6問）は幅5列のAREA連鎖と外周捕獲を組み合わせた手設計です。Stage 4のWave 1–2（4問）は奥行7列、Wave 3–4（4問）は奥行8列で、長いAREA連鎖と外周の間隔・遅延・切り返しを手設計で学ばせます。Stage 5のWave 1–2（6問）は幅6列へ広げ、左右のAREA帯と外周レーンを入れ替える手設計です。Stage 5 Wave 3以降は決定的な制約付き生成へ戻り、保護・連鎖・持ち越しAREAを段階的に追加します。

## デバッグモード

URLへ`?debug=1`を付けると、通常プレイには出ないデバッグパネルが有効になります。現在座標とゲーム状態を確認でき、STEPで1回転を進め、AUTOで必要キューブの自動解法を実行し、+ROWで足場列を増やせます。`?demo`は目視検査用の決定的な自動プレイを開始します。

## 実装と性能

ゲーム状態は30Hz固定ステップで更新し、キューブ、MARK、AREA、得点、回転数、足場列を整数グリッドで管理します。Babylon.jsの表示は補間・カメラ・影・粒子風の光だけを担当します。端末性能は論理コア数、メモリー、画面幅からLOW／NORMAL／HIGHを安全側で選び、DPR換算を抑え、低性能端末では影とGlowの負荷を下げます。ページを隠したときはゲームを自動一時停止します。

## 既知の事項

Babylon.jsは`GameCanvas`の遅延境界に置かれ、タイトル初期表示には読み込みません。遅延ランタイム自体は大きいため、現在値はGitHub Actionsの最新`pnpm build`を正とします。音はブラウザの自動再生制限を守るため、最初のユーザー入力後にWeb Audio APIで有効化されます。現在の床・背景・ロゴはCSSとBabylonの手続き生成で描画し、ゲームプレイは外部画像ストレージに依存しません。`/manus-storage/*`はExpress検査用の互換ルートです。
